# Security

Security is a foundation requirement. This document records the threat model and the controls that exist today, and marks what is planned.

## Principles

- Authorization is enforced server-side on every protected operation; hiding UI is never authorization.
- Tenant isolation is enforced twice: by application scoping and by Postgres Row-Level Security.
- Staff are least-privileged: DB-resolved permissions, step-up for privileged actions, no customer content by default.
- Every privileged or denied action is written to an append-only, hash-chained audit log.
- Secrets never live in files or the browser; they are validated at boot and redacted from logs.
- Untrusted input (URLs, uploads, repository content, AI output) is data, never instructions or code.

## Privacy

- Regimes: Nigeria Data Protection Act 2023 (NDPC), GDPR/UK GDPR for EU/UK customers.
- Processor register (to be maintained in OPERATIONS.md as integrations land): Neon, Cloudflare, Fly.io, email provider, AI/voice vendors, payment providers.
- Deletion: Better Auth `deleteUser` is enabled; a full org deletion workflow (DB rows, object storage, provider-side files) lands with the asset model in Phase 2.
- Logging: prompt bodies, asset contents and secrets never go to logs or traces.

## Reporting

Security issues: see `SECURITY` contact in the organisation profile (to be published before public launch). Do not open public issues for vulnerabilities.
